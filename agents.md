# Agent Instructions & Guidelines

## Formatting & Behavior
- Never use em-dashes. Always use plain dashes (-) instead to maintain a human-written aesthetic.
- When writing commit messages, never auto-add your agent name or co-author tags. The human developer is ultimately accountable.
- Never manually modify CHANGELOG.md or any other files flagged as autogenerated.

## Technical Decision Making
- When making technical or architectural decisions, do not prioritize short-term development costs. Instead, heavily favor:
  1. Code quality and readability
  2. Simplicity and minimalist architectures
  3. Robustness and error resilience
  4. Scalability and long-term maintainability
- Resist the bias of choosing "cheap" or "quick" solutions simply because standard human metrics estimate them as high-effort.

## Debugging and Fixing Bugs
- Always start bug fixes by reproducing the bug in an end-to-end setting. This setting should mimic the end-user experience as closely as possible before proposing any changes.

## Engineering Standards
- Be picky about the UI and UX. Maintain an absolute obsession with pixel perfection. If something looks misaligned or off, patch it along the way.
- Apply strict engineering excellence. Fix linter complaints, warnings, and test flakiness immediately, even if they were not caused by the current task.
